# 基于 K-means 的交通信号控制时段划分

本项目是一个 **Python 数据分析程序**，用于自动把一天 24 小时划分为若干 **交通控制时段**（control period）。它读取一个干道信号控制交叉口**连续多天的逐小时流量数据**，通过 **K-means 聚类算法**将 24 个小时聚类成不同"流量模式"的类别，再经 **时间连续性后处理** 输出可以直接用于信号配时方案设计的连续时段。

## 1. 项目简介

交通信号控制中，一天中不同时间段的交通流量差异巨大（如早高峰、平峰、晚高峰、夜间低峰）。传统做法依靠人工经验划分时段；本项目用数据驱动的方式，利用多天流量的统计特征自动识别这些时段，为 **分时段信号配时（多时段控制）** 提供依据。

核心思想：

- 以 **小时** 为基本时间单位（一天共 24 个样本点）；
- 每个样本点的特征是 **各个流向的流量值**；
- 将流量特征相近的小时归为一类，即同一个控制时段。

```
多天流量数据（JSON）
        │
        ▼
① 按小时聚合（多天 → 一天代表值，取中位数）
        │
        ▼
② 构建特征矩阵 X（24 行 × n 个流向）
        │
        ▼
③ Z-score 标准化（消除量纲差异）
        │
        ▼
④ 轮廓系数法自动选择最优聚类数 K
        │
        ▼
⑤ K-means 聚类（把 24 小时分成 K 类）
        │
        ▼
⑥ 时间连续性后处理（合并短段、跨零点合并）
        │
        ▼
输出：连续的控制时段 [start_hour, end_hour)
```

## 2. 功能特性

- ✅ **多天数据聚合**：按小时、按流向取**中位数**，把多天数据压缩成一天的代表性数据，抗单日偶发波动；
- ✅ **自动选择 K**：通过**轮廓系数（Silhouette Score）**在 K = 4~8 范围内自动选取最优聚类数，无需手动指定；
- ✅ **标准化处理**：Z-score 归一化，消除不同流向间流量量纲的差异；
- ✅ **时间连续性保证**：聚类后处理确保时段在时间上连续，并自动处理**跨零点**的连续时段（如晚高峰延续至次日凌晨）；
- ✅ **完全可复现**：固定随机种子（`random_state=0`），多次运行结果一致；
- ✅ **输出结构化**：返回最佳 K、逐小时标签、连续时段段列表及标准化参数，便于二次开发。

## 5. 数据格式说明

输入文件 `数据.json` 的结构如下：

```json
{
  "intersection_id": "I-001",
  "description": "干道信号控制交叉口5天交通流量模拟数据（每小时统计，分进口方向，pcu/h）",
  "flow_names": ["南直行", "北直行", "南左转", "北左转",
                 "东直行", "西直行", "东左转", "西左转"],
  "days": [
    {
      "day": "Day1",
      "hours": [
        {"hour": 0, "flows": [92, 100, 31, 32, 75, 88, 21, 20]},
        {"hour": 1, "flows": [89, 98, 29, 26, 71, 75, 22, 20]},
        ...
      ]
    },
    { "...": "Day2 ... Day5 结构与 Day1 相同" }
  ]
}
```

关键字段说明：

| 字段 | 含义 |
| --- | --- |
| `intersection_id` | 交叉口编号（仅作标识，不参与计算） |
| `description` | 数据描述 |
| `flow_names` | 流向名称列表，顺序必须与每小时的 `flows` 数组一一对应 |
| `days` | 多天数据的数组，**每天必须包含完整的 24 个小时**（hour 0~23） |
| `hours[].hour` | 小时编号，取值 0~23 |
| `hours[].flows` | 该小时各流向的流量值数组（单位：pcu/h），长度必须等于 `flow_names` 的长度 |

> **注意：**
> - 本项目示例共 **8 个流向**，按进口方向区分：`南直行、北直行、南左转、北左转、东直行、西直行、东左转、西左转`，每小时的 `flows` 数组长度必须与此一致；
> - 每天必须提供完整 24 小时数据，缺小时会导致聚类结果错位；
> - 各天的流向顺序必须完全一致；
> - 流量单位建议统一（本项目示例为 pcu/h）。

## 6. 使用方法

在项目根目录直接运行：

```bash
python k-means.py
```

程序会自动读取同目录下的 `数据.json`，执行完整分析流程，并在控制台输出结果。

### 6.1 在代码中调用

```python
import json
from k-means import KM

with open("数据.json", "r", encoding="utf-8") as f:
    data = json.load(f)

km = KM(data)
result = km.run()

print("最佳聚类数:", result['best_k'])            # int
print("逐小时标签:", result['labels'])            # np.ndarray, 长度 24
print("控制时段:")
for seg in result['segments']:                     # list[dict]
    print(f"  {seg['start_hour']:02d}:00 - {seg['end_hour']:02d}:00, 类别 {seg['label']}")
```

  -3:00 - 06:00, 类别 2
  06:00 - 07:00, 类别 0

从输出可以看出，程序自动识别出了 **夜间低峰（21:00~06:00，跨零点）→ 早高峰（07:00~10:00）→ 平峰（10:00~17:00）→ 晚高峰（17:00~19:00）** 等典型时段。其中类别 `0`（平峰/过渡模式）在 06:00、10:00~17:00、20:00~21:00 多次出现，属于同一流量模式在时间上的重复。

> 注：`-3:00 - 06:00` 表示**跨零点**的连续时段，即前一天 21:00 至当日 06:00。`end_hour` 为**不包含**的边界（左闭右开区间 `[start, end)`）。

## 7. 算法原理详解（重点）

### 7.0 整体流程

`KM` 类的 `run()` 方法依次调用 6 个步骤，返回一个字典：

```python
def run(self):
    Z, mean, std = self.standardize()          # ③ 标准化
    best_k, scores = self.find_optimal_k(Z)    # ④ 选 K
    labels, kmeans = self.kmeans_cluster(Z, best_k)  # ⑤ 聚类
    segments = self.postprocess_labels(labels) # ⑥ 后处理
    return {...}
```

下面逐步说明每一步的输入、输出与数学原理。

---

### 7.1 步骤①：多天数据聚合 —— 按小时取中位数

**输入**：多天、每天 24 小时的原始流量数据。
**输出**：一天 24 小时、每个流向一个代表值的"代表性一天"数据。

**思路**：聚类需要把 24 个小时看作 24 个样本点。但数据是多天的，同一个小时（如每天 7 点）有多个观测值。必须把多天压缩成一天的代表值。

**方法**：对每个小时 `h`（0~23）和每个流向 `f`，收集所有天在此时刻的流量值，取**中位数**：

```
median_hours[h].flows[f] = median( Day1[h][f], Day2[h][f], ..., DayD[h][f] )
```

**为什么用中位数而不是平均值？**
中位数对**离群值（异常值）更鲁棒**。某一天某一小时因事故、天气等原因出现极端流量时，平均值会被拉偏，而中位数基本不受影响，能更真实地反映该时段的"典型"交通状态。

---

### 7.2 步骤②：构建特征矩阵 X

**输入**：聚合后的一天代表性数据。
**输出**：`X`，一个 **24 × n** 的 numpy 二维数组（n 为流向数量）。

```python
X = np.array([hour['flows'] for hour in hours])   # shape = (24, n)
```

- 第 `i` 行：第 `i` 个小时的特征向量；
- 第 `j` 列：第 `j` 个流向；
- `X[i][j]` = 第 `i` 小时、第 `j` 流向的代表性流量。

每个小时即 K-means 中的一个**样本点**，共有 24 个样本，每个样本有 n 个特征。

---

### 7.3 步骤③：Z-score 标准化

**输入**：特征矩阵 `X`（24 × n）。
**输出**：标准化矩阵 `Z`，以及各列的均值 `mean` 与标准差 `std`。

**目的**：不同流向的流量量纲差异巨大（例如晚高峰北直行可达 850+ pcu/h，而夜间南左转只有十几）。若不标准化，K-means 的欧氏距离会被数值大的特征主导，导致聚类结果失真。

**公式**（对每一列 / 每一个流向独立计算）：

```
Z[i][j] = ( X[i][j] - μ_j ) / σ_j

其中：μ_j = mean( X[:, j] )   —— 第 j 个流向的均值
      σ_j = std( X[:, j] )    —— 第 j 个流向的标准差
```

标准化后，每个流向的数据均值为 0、标准差为 1，各流向在距离计算中**权重相同**。

**数值处理**：当某个流向 24 小时流量完全不变时，`σ_j = 0`，会除零。代码将 `σ_j` 置为 1：

```python
std[std == 0] = 1
```

---

### 7.4 步骤④：轮廓系数法自动选择最优聚类数 K

**输入**：标准化矩阵 `Z`。
**输出**：最优聚类数 `best_k`，及各候选 K 的轮廓系数列表 `scores`。

**背景**：K-means 要求预先指定簇数 K。K 选多了会过分割，选少了会欠拟合。本项目用**轮廓系数（Silhouette Coefficient）**作为评价指标，在 `K ∈ {4, 5, 6, 7, 8}` 中挑选得分最高者。

**轮廓系数计算**（对每个样本点 i）：

```
a(i) = 样本 i 到同一簇内其他样本的平均距离       —— 簇内紧密度
b(i) = 样本 i 到最近的其他簇所有样本的平均距离   —— 簇间分离度

s(i) = ( b(i) - a(i) ) / max( a(i), b(i) )

轮廓系数 = 所有样本 s(i) 的均值
```

- `s(i) ∈ [-1, 1]`；
- 接近 **1**：样本离自己簇很近、离别的簇很远 → 聚类效果好；
- 接近 **0**：样本位于两个簇的边界，模糊；
- 接近 **-1**：样本可能被分错了簇。

**过程**：

1. 对 K = 4, 5, 6, 7, 8 依次执行 K-means 聚类；
2. 每次聚类后计算轮廓系数；
3. 取轮廓系数**最大**对应的 K 作为最优聚类数。

```python
best_k = k_range[np.argmax(scores)]   # k_range = range(4, 9)
```

> **关于随机性**：K-means 初始化具有随机性。代码固定 `random_state=0`，并用 `n_init=10`（用 10 个不同初始质心运行，取目标函数最小者），保证结果**可复现且不易落入局部最优**。

---

### 7.5 步骤⑤：K-means 聚类

**输入**：标准化矩阵 `Z`（24 个样本点）与最优 K。
**输出**：长度 24 的标签数组 `labels`（每个小时一个类别，取值 0 ~ K-1），以及训练好的 `kmeans` 模型。

**K-means 算法核心步骤**：

设共有 N 个样本点（此处 N = 24），要聚成 K 个簇：

1. **初始化**：随机选取 K 个样本作为初始质心（centroid）`μ₁, μ₂, ..., μ_K`；
2. **分配（Assignment）**：对每个样本点 `z_i`，计算其到各质心的**欧氏距离**，将其分配到距离最近的质心所属簇：
   ```
   c_i = argmin_j  ‖ z_i - μ_j ‖₂
   ```
3. **更新（Update）**：重新计算每个簇的质心为簇内所有样本的**均值**：
   ```
   μ_j = (1 / |C_j|) · Σ_{z_i ∈ C_j} z_i
   ```
4. **迭代**：重复步骤 2、3，直到质心不再移动（或达到最大迭代次数 / 目标函数变化小于阈值）。

**目标函数**（簇内误差平方和，SSE / inertia）：

```
minimize  J = Σ_{j=1..K} Σ_{z_i ∈ C_j} ‖ z_i - μ_j ‖₂²
```

**实现**：直接调用 `sklearn.cluster.KMeans`：

```python
kmeans = KMeans(n_clusters=k, random_state=0, n_init=10)
labels = kmeans.fit_predict(Z)
```

**结果**：得到 24 个小时各自归属的类别，例如 `labels = [1 1 1 ... 3 2 2 3 ...]`，表示第 0~2 小时属于类别 1、第 17~18 小时属于类别 2 等。

---

### 7.6 步骤⑥：时间连续性后处理

**输入**：逐小时标签 `labels`（长度 24）。
**输出**：连续控制时段列表 `segments`，每个元素形如 `{start_hour, end_hour, label}`。

**目的**：K-means 只关注特征相似性，不关心时间顺序，可能出现"同一类别的小时被切开"或"单小时孤立类别"的情况。而交通控制要求时段**在时间上连续、可执行**，因此需要后处理。

**子步骤 1：合并相邻同类小时**

从左到右扫描 24 个标签，把连续且类别相同的相邻小时合并成一段：

```python
segments = [{'start_hour': 0, 'end_hour': 6, 'label': 1},
            {'start_hour': 6, 'end_hour': 7, 'label': 4}, ...]
```

`end_hour` 为不包含的小时，即时段覆盖 `[start_hour, end_hour)`。

**子步骤 2：合并孤立短时段**

对长度小于 `min_duration`（最短时段长度，默认 `1`）的段，合并到前一段中：

```python
if dur >= min_duration:
    processed.append(seg)
else:
    prev = processed[-1]
    prev['end_hour'] = seg['end_hour']   # 并入前一段
```

> **说明**：因任何段的长度至少为 1 小时，默认 `min_duration=1` 时本子步骤几乎不生效。若希望**将单小时的孤立类别并入相邻时段**（例如只有 1 小时的"怪"时段），可调用 `postprocess_labels(labels, min_duration=2)` 实现。

**子步骤 3：跨零点合并**

交通流量往往在夜间低位连续（如 22:00 ~ 次日 06:00 同属低峰）。若首段与末段类别相同，说明该类别"跨过零点"延续，需首尾合并：

```python
if processed[0]['label'] == processed[-1]['label']:
    first['start_hour'] = last['start_hour'] - 24   # 用负数表示跨日
    processed.pop()
```

例如末段为 `[22, 24)`、首段为 `[0, 6)` 且类别同为 1，则合并后首段变为 `start_hour = 22 - 24 = -2`，输出 `-2:00 - 06:00, 类别 1`，代表前一天 22:00 至当日 06:00 的连续夜间低峰。

---

### 7.7 输出字段一览

`run()` 返回的字典包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `best_k` | `int` | 轮廓系数法选出的最优聚类数 |

## 8. 参数说明

| 参数 | 位置 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `k_range` | `find_optimal_k` | `range(4, 9)` | 候选聚类数范围，即 K 取 4~8 |
| `random_state` | K-means | `0` | 随机种子，保证结果可复现 |
| `n_init` | K-means | `10` | 初始化次数，取多次中 SSE 最小者 |

## 9. 注意事项与已知问题

- **Windows / MKL 警告**：在 Windows 上运行时，sklearn 可能打印
  `KMeans is known to have a memory leak on Windows with MKL...` 警告。
  这不影响结果，可忽略；或设置环境变量 `OMP_NUM_THREADS=1` 规避。
- **CPU 限制**：代码设置了 `os.environ["LOKY_MAX_CPU_COUNT"] = "4"`，
  用于限制 scikit-learn 并行计算使用的 CPU 数，避免在受限环境下报错，可按需调整。
- **输入完整性**：每天必须 24 小时齐全、流向数一致，否则特征矩阵会错位。
- **K 的范围**：默认 K 取 4~8，是针对本项目 24 小时样本点的合理区间；
  数据量或交通特性差异较大时可调整 `k_range`。
- **中位数聚合**：若只有 1 天数据，中位数即原始值，聚合步骤退化为透传。

## 10. 可扩展方向

本项目是完整可运行的最小实现，以下方向可在此基础上扩展：

1. **时段数确定优化**：除轮廓系数外，可对比肘部法则（Elbow）、Davies-Bouldin 指数等；
2. **特征扩展**：加入速度、排队长度、饱和度等更多特征，得到更丰富的时段划分；
3. **可视化**：绘制 24 小时流量曲线并按类别着色、绘制质心随小时的变化；
4. **输入接口**：支持 CSV / Excel / 数据库读取，替代 JSON；
5. **平滑处理**：在后处理阶段加入"最短时段 + 相邻类合并"的更完善规则，避免时段过于细碎；
6. **导出配时方案**：将 `segments` 直接输出为信号机可导入的多时段配时表。
